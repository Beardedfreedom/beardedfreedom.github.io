# Legal, open-data and commercially licensed sources for a single-property 3D site model (US, as of Sept 2026)

Scope note for the report writer: this file covers the *fully legal* data-acquisition path from a US street address to files on disk (LAZ/LAS point cloud, DEM GeoTIFF, contours, parcel polygon, building footprints, orthoimagery, optional textured mesh) for import into AutoCAD / Civil 3D, plus the drone-photogrammetry and professional-survey options. Research constraint: the sandbox egress proxy blocked direct fetches of usgs.gov, opentopography.org, faa.gov, regrid.com, nearmap.com, maxar.com, pdal.io, developers.google.com and planetarycomputer.microsoft.com; facts from those domains below come from search-engine summaries of those pages (URL cited) or from primary docs mirrored on GitHub. Where a number could not be confirmed against the primary page it is flagged.

## Key Question 1: Geocoding an address to coordinates and to a parcel (county GIS, Regrid, accuracy vs. survey)

### Takeaway
Free federal geocoding (Census Geocoder) plus a county ArcGIS REST "parcels" FeatureServer query (`f=geojson`) gets you a parcel polygon at zero cost; Regrid is the national paid fallback (self-serve API with 2,000 records/month included; $400 for a whole-county premium shapefile). County GIS parcel lines are routinely 5–20 ft off the true boundary and every county disclaims them for legal use, so the polygon is a base-map reference only until a surveyor stakes the lot.

### Cited Findings
**Geocoding**
- The US Census Bureau offers a free geocoding API with a `onelineaddress` endpoint that accepts a single address string, e.g. `https://geocoding.geo.census.gov/geocoder/locations/onelineaddress?address=4600+Silver+Hill+Rd,+Suitland,+MD+20746&benchmark=9&format=json`; `benchmark` selects the address dataset and `format` selects json/jsonp. Batch geocoding accepts CSV/TXT/DAT/XLS/XLSX uploads — [Census Geocoding Services API PDF](https://geocoding.geo.census.gov/geocoder/Geocoding_Services_API.pdf); [NICAR20 geocoding APIs repo](https://github.com/jsoma/NICAR20-geocoding-apis)
- A lightweight Python wrapper (`censusgeocode`) with a CLI geocodes a single address to lon/lat or a batch file — [censusgeocode on PyPI](https://pypi.org/project/censusgeocode/)
- Regrid also sells a Typeahead address-autocomplete API at $0.001 per request — [VA Horizon property-data API cost comparison](https://www.vahorizon.site/blog/property-data-api-costs-for-wholesalers/)

**County / state parcel GIS (free)**
- Esri feature-service query pattern: `.../FeatureServer/0/query?where=<SQL>&outFields=*&returnGeometry=true&f=geojson`; valid `f` values include html, json, geojson, kmz, amf; `where` is a SQL clause, `outFields` selects attributes — [Esri: Query (Feature Service/Layer)](https://developers.arcgis.com/rest/services-reference/enterprise/query-feature-service-layer/); [Esri: Output formats](https://developers.arcgis.com/rest/services-reference/enterprise/output-formats/)
- Example of a public county parcel FeatureServer endpoint: Sonoma County `https://socogis.sonomacounty.ca.gov/map/rest/services/rovpublic/Parcel_2024_2025/FeatureServer` (and a geometry-only MapServer at `.../CRAPublic/Parcel_Geometry_Only/MapServer`) — [Sonoma County GIS REST](https://socogis.sonomacounty.ca.gov/map/rest/services/rovpublic/Parcel_2024_2025/FeatureServer)
- Esri's own docs use the LA County Parcels layer (2.4 million features) as the example of `where`-filtered queries with `outFields=APN,UseType,TaxRateCity` and `resultRecordCount` — [Esri: Query features](https://developers.arcgis.com/documentation/portal-and-data-services/data-services/feature-services/query-features/)
- King County (WA) open-data portal exposes ~600 datasets (parcels, contours, imagery, etc.) with the option to download or connect via API — [King County GIS Open Data – Download](https://gis-kingcounty.opendata.arcgis.com/pages/download-gis-data); [King County GIS Center data hub](https://kingcounty.gov/en/dept/kcit/data-information-services/gis-center/data-hub)

**Regrid (paid national parcel source)**
- Regrid Self-Serve monthly API plans use a hybrid model: each monthly plan includes 2,000 parcel records and 200,000 tiles; Standard charges $0.10 per additional parcel record, Premium $0.15; both charge $0.001 per additional tile. Changelog version v2025.9.23 — [Regrid support changelog: Self-serve API plans](https://support.regrid.com/changelog/self-serve-api-plans); [Regrid self-serve API plans page](https://app.regrid.com/api/plans)
- The base monthly subscription price is only visible after creating an account; larger volumes go through enterprise sales — [Regrid Parcel API](https://regrid.com/parcel-api); [Regrid plans](https://app.regrid.com/plans)
- Pay-to-Download: a county shapefile with all Premium fields and parcel geometry (including vacancy and building counts) costs $400; purchasable per county at app.regrid.com/store as spreadsheet or shapefile; download link stays active one month; Pro/Team customers can export per-parcel from the Property App — [Regrid: Pay-to-download parcel data](https://regrid.com/pay-to-download-parcel-data); [Regrid blog: Data Store](https://regrid.com/blog/datastore); [Regrid blog: Pay to Download launch](https://regrid.com/blog/regrid-launches-pay-to-download)

**Accuracy of GIS parcel lines vs. recorded survey**
- "It is normal for a GIS line to be off by five, ten, or even twenty feet"; GIS portals include a disclaimer that data is not survey-accurate — [Godfrey Hoffman Hodge: Understanding Town GIS Portals](https://ghhllc.com/blog/understanding-town-gis-portals-what-those-lines-really-mean)
- County GIS parcel boundaries "are not of survey-grade quality and should not be used for legal purposes or be represented as surveyed boundaries"; building a fence, driveway, shed or pool from a GIS line can create an encroachment — [Aspyre Realty: Survey vs Plat Map vs GIS](https://aspyrerealtygroup.com/survey-vs-plat-map-why-you-cant-just-rely-on-the-county-gis-line/)
- Typical county disclaimer (Tuolumne County, CA): parcel data "may or may not represent legal parcels… shapes, angles, and dimensions… are not exact"; only legally recorded parcel maps should be used for measurement or design work — [Tuolumne County GIS Layer Descriptions](https://tuolumnecounty.ca.gov/524/GIS-Layer-Descriptions)
- Massachusetts: parcel polygons are "approximate and were developed primarily for planning purposes… should not be relied upon in matters requiring delineation of true ground controls" — [Mass.gov disclaimers for maps and data](https://www.mass.gov/info-details/disclaimers-for-maps-and-data)
- GIS-computed acreage depends on the source scale from which the parcel was digitized — [AcreValue: How accurate is a property lines map?](https://www.acrevalue.com/resources/blog/how-accurate-is-a-property-lines-map/)

### Inferences
- A no-cost address→parcel chain is: Census `onelineaddress` (lon/lat) → county/state ArcGIS REST parcel layer query with a spatial `geometry=<x,y>&geometryType=esriGeometryPoint&inSR=4326&outSR=<state plane or 4326>&f=geojson` (the point-in-polygon form of the query documented above) → save GeoJSON → convert to DXF/SHP with GDAL/QGIS. Many counties also let you type the address directly into the parcel viewer and download the shapefile.
- Because the parcel polygon can be off by several feet to ~20 ft, it should be placed on its own "REFERENCE-GIS" layer in the DWG and never used to set setbacks for permit drawings; the recorded plat/deed bearings-and-distances (drawn with Civil 3D's parcel-by-metes-and-bounds tools) or a boundary survey should replace it before design.

### Gaps
- Regrid's base monthly price for the Standard/Premium self-serve API plans is behind an account wall and was not found in any public source.
- OSM's Nominatim geocoder was not fetched (host blocked); its usage policy (1 request/second, attribution, ODbL) is well known but could not be cited here.
- No single national list of county parcel REST endpoints was found; the report should instruct users to search "<county> GIS parcels FeatureServer" or use state clearinghouses.

## Key Question 2: USGS 3DEP lidar — coverage, quality levels, how to clip a small area (TNM, EPT/PDAL, OpenTopography, state portals), licensing, accuracy, classification, building reconstruction

### Takeaway
At the end of FY2025, 99% of the nation had 3DEP-quality lidar available or in progress; QL2 (≥2 pts/m², 10 cm RMSEz) is the minimum and all of it is US-government public domain. For a single lot the fastest legal path is PDAL `readers.ept` with a `bounds` clip against the public `s3://usgs-lidar-public` EPT bucket (EPSG:3857), or The National Map/TNMAccess to pull the LAZ tile; building roof points are class 6 and can be used to estimate heights or reconstruct roof planes, but full LoD2 reconstruction remains research-grade.

### Cited Findings
**Coverage / program status (2025–2026)**
- At the end of FY2025, 99% of the Nation has baseline data available or in progress that meet 3DEP specifications; "baseline" is defined as QL2 or better lidar (IfSAR in Alaska) that is 8 years old or newer — [USGS: What is 3DEP?](https://www.usgs.gov/3d-elevation-program/what-3dep); [USGS: FY25 Status of 3DEP Quality Data](https://www.usgs.gov/media/images/fy25-status-3dep-quality-data)
- The FY26 map shows 3DEP projects and status of both bare-earth and point-cloud coverage including "baseline and next generation coverage"; FY26 projects came through the 3D National Topography Model (3DNTM) Data Collaboration Announcement — [USGS: 3DEP FY2026 partnerships map](https://www.usgs.gov/media/images/usgs-3d-elevation-program-fiscal-year-2026-partnerships)
- Status maps: TNM Download Client, Lidar Availability Viewer, LidarExplorer, DEM Availability Viewer — [USGS FAQ: 3DEP product updates and status maps](https://www.usgs.gov/faqs/where-can-i-find-3d-elevation-program-3dep-product-updates-and-status-maps)
- OpenTopography reports "over 1800 3DEP datasets consisting of more than 42 trillion points covering an area of greater than 6.5 million km²" in the AWS EPT bucket — [OpenTopography: Accessing USGS 3DEP data](https://opentopography.org/content/accessing-usgs-3dep-data-opentopography) (older Hobu figure: >10 trillion points in >950 resources — [hobuinc/usgs-lidar](https://github.com/hobuinc/usgs-lidar))

**Quality levels and accuracy (Lidar Base Specification)**
- QL2: nominal pulse density ≥2 pts/m², nominal pulse spacing ≤0.71 m, 10.0 cm RMSEz (aligned with the ASPRS 10-cm vertical accuracy class); QL2 is the minimum acceptable quality level for 3DEP — [USGS: Topographic Data Quality Levels](https://www.usgs.gov/3d-elevation-program/topographic-data-quality-levels-qls); [USGS: LBS Collection Requirements](https://www.usgs.gov/ngp-standards-and-specifications/lidar-base-specification-collection-requirements)
- QL1: aggregate nominal pulse spacing 0.35 m, 8 pts/m²; QL0: 0.18 m, 30 pts/m² (highest level) — [Minnesota 2025 0.5 m DEM metadata](https://mnatlas.org/metadata/dem_lidar_2025.html); [3D Nation Study FAQs (NOAA)](https://iocm.noaa.gov/reports/3dnationstudy/Appendix_B_FAQs.pdf)
- Non-vegetated vertical accuracy (NVA) is assessed against survey-grade GNSS checkpoints — [3DEP Lidar Base Specification 2022 rev. A (PDF mirror)](https://www.merrick.com/site/static/mars/documentation/Lidar-Base-Specification-2022-rev-A.pdf)
- Independent systematic analysis of 3DEP accuracy/consistency — [MDPI Remote Sensing 14(4):940](https://www.mdpi.com/2072-4292/14/4/940)
- FEMA has standardized on QL2 as defined in the USGS LBS for new lidar acquisition — [FEMA Elevation Guidance, Nov 2022](https://www.fema.gov/sites/default/files/documents/fema_elevation-guidance_112022.pdf)

**Point classification**
- 3DEP LBS: "the minimum required classification scheme for lidar data is found in table 5"; all points within the minimum scheme and not flagged withheld shall be properly classified — [USGS: LBS Data Processing and Handling Requirements](https://www.usgs.gov/ngp-standards-and-specifications/lidar-base-specification-data-processing-and-handling-requirements)
- ASPRS LAS 1.4 codes: class 2 = ground, class 6 = building (also 1 unclassified, 3/4/5 low/medium/high vegetation, 7 low noise, 9 water, 17 bridge deck, 18 high noise) — [LidarVisor: ASPRS classification codes](https://lidarvisor.com/lidar-classification-codes/); [Esri: Lidar point classification](https://desktop.arcgis.com/en/arcmap/latest/manage-data/las-dataset/lidar-point-classification.htm)

**Licensing**
- License: "US Government Public Domain" per USGS terms of use for map services and data — [AWS Open Data Registry YAML: usgs-lidar](https://github.com/awslabs/open-data-registry/blob/main/datasets/usgs-lidar.yaml)
- USGS 3DEP 1 m DEM in Earth Engine: "Most U.S. Geological Survey (USGS) information resides in the public domain and may be used without restriction" (attribution requested) — [Earth Engine catalog source: USGS_3DEP_1m.jsonnet](https://github.com/google/earthengine-catalog/blob/main/catalog/USGS/USGS_3DEP_1m.jsonnet)

**Download path A — The National Map / TNMAccess (LAZ tiles, DEMs)**
- TNMAccess is the single API for all TNM downloadable products; supports HTTP GET/POST; parameters include `bbox` (minx,miny,maxx,maxy in decimal degrees), `datasets`, `prodFormats` (e.g. LAS, LAZ), `polygon`, `prodExtents`, date ranges, output format; endpoints return product results and dataset results — [TNMAccess API docs](https://tnmaccess.nationalmap.gov/api/v1/docs); [USGS FAQ: Is there an API for accessing National Map data?](https://usgs.gov/faqs/there-api-accessing-national-map-data)
- Datasets reachable via TNMAccess include 3DEP elevation (DEMs and lidar point clouds), US Topo, NHD, NLCD, National Structures, Transportation, Boundaries; there is a 50-file limit per request when downloading tiles — [UA Libraries: USGS National Map API in Python](https://ua-libraries-research-data-services.github.io/UALIB_ScholarlyAPI_Cookbook/python/usgs-national-map.html)
- TNM Download Client: click "Search Products", then download individual files or use the cart for batch downloads — [USGS FAQ: How do I download National Map data products?](https://www.usgs.gov/faqs/how-do-i-download-national-map-data-products)
- LidarExplorer searches and visualizes lidar, DEM, topobathy and ORI products, uses EPT for a web 3D viewer and identifies projects with 3D visualization enabled — [USGS: LidarExplorer](https://www.usgs.gov/tools/lidarexplorer); [USGS FAQ: What is lidar data and where can I download it?](https://www.usgs.gov/faqs/what-lidar-data-and-where-can-i-download-it)
- Staged TNM products (LAZ tiles, DEMs, project reports) live in the public S3 bucket `prd-tnm` under `StagedProducts/Elevation/...` (example: an Illinois 2023 lidar mapping report at `https://prd-tnm.s3.amazonaws.com/StagedProducts/Elevation/metadata/IL_10CountyNRCS_D23/...`) — [example staged product URL](https://prd-tnm.s3.amazonaws.com/StagedProducts/Elevation/metadata/IL_10CountyNRCS_D23/IL_10CoNRCS_2_D23/reports/Lidar_Report/140G0223F0169-IL_10CountyNRCS_D23_WU_ID300581_Lidar_Mapping_Report.pdf)
- Community CLI tool that discovers and downloads 3DEP LAZ tiles from TNM — [wangsen992/usgs-lidar-downloader](https://github.com/wangsen992/usgs-lidar-downloader)
- Lidar Point Cloud (LPC) collection record — [USGS Science Data Catalog](https://data.usgs.gov/datacatalog/data/USGS:b7e353d2-325f-4fc6-8d95-01254705638a)

**Download path B — AWS Entwine Point Tiles (EPT) + PDAL**
- Two buckets, both in us-west-2: `s3://usgs-lidar` (Requester Pays; full-density LASzip tiles) and `s3://usgs-lidar-public` (public access; EPT resources). EPT is a lossless, streamable octree based on LAZ encoding. Updated "periodically". STAC catalog: `https://usgs-lidar-stac.s3-us-west-2.amazonaws.com/ept/catalog.json` — [AWS Registry: USGS 3DEP LiDAR Point Clouds](https://registry.opendata.aws/usgs-lidar/); [registry YAML](https://github.com/awslabs/open-data-registry/blob/main/datasets/usgs-lidar.yaml)
- Organization: one EPT resource per USGS project; data reprojected to EPSG:3857 "for ease of web usage"; a `/boundaries` folder (GeoJSON) indexes which resource covers an area; Hobu built it with Entwine on EC2 and hosts a map at usgs.entwine.io — [hobuinc/usgs-lidar](https://github.com/hobuinc/usgs-lidar); [USGS technical announcement](https://www.usgs.gov/news/technical-announcement/usgs-3dep-lidar-point-cloud-now-available-amazon-public-dataset)
- PDAL `readers.ept` `bounds` option: "extents of the resource to select in 2 or 3 dimensions, expressed as a string in the format `([xmin, xmax], [ymin, ymax], [zmin, zmax])`"; may be followed by `/` and a spatial reference (e.g. `/EPSG:4326`) to apply to the bounds; if omitted the entire dataset is read (Iowa ≈160 billion points). Example bounds: `([-8242669, -8242529], [4966549, 4966674])` — [PDAL readers.ept](https://pdal.io/en/stable/stages/readers.ept.html); [PDAL tutorial: Reading data from EPT (Iowa)](https://pdal.io/en/stable/tutorial/iowa-entwine.html)
- OpenTopography's OT_3DEP_Workflows: seven Jupyter notebooks that read 3DEP EPT from S3 with PDAL, generate DTM/DSM/CHM and difference maps, colorize with NAIP, and clip by user AOI, USGS 7.5' quad, HUC or corridor; dependencies gdal, geopandas, ipyleaflet, matplotlib, pdal, pyproj, requests, rioxarray — [OpenTopography/OT_3DEP_Workflows](https://github.com/OpenTopography/OT_3DEP_Workflows); [notebook 01: Generate DEM for user AOI](https://github.com/OpenTopography/OT_3DEP_Workflows/blob/main/notebooks/01_3DEP_Generate_DEM_User_AOI.ipynb)
- Example community workspace listing/downloading LAS from EPT via `ept.json` — [salvaleonrp/di-ept-json-lidar](https://github.com/salvaleonrp/di-ept-json-lidar)

**Download path C — OpenTopography portal/API**
- OpenTopography requires an API key; free key is rate-limited to 200 calls/24 h for academics and 50 calls/24 h for non-academics; OT+ subscription unlocks higher limits; Enterprise key for commercial integration; keys may not be shared or published — [OpenTopography: Introducing API keys](https://opentopography.org/blog/introducing-api-keys-access-opentopography-global-datasets); [OpenTopography API docs](https://portal.opentopography.org/apidocs/)
- 3DEP point clouds are available through the OpenTopography Data Portal (hosted from the AWS EPT bucket) with cloud processing to generate custom DEMs, hillshade, slope/aspect etc. without downloading raw data — [OpenTopography: Accessing USGS 3DEP data](https://opentopography.org/content/accessing-usgs-3dep-data-opentopography); [OpenTopography developers page](https://opentopography.org/developers)
- OT+ (OpenTopography Plus) is the subscription for non-academic users to access "the highest-quality lidar topography for North America"; pricing is not published (contact info@opentopography.org) — [OpenTopography: OT+](https://opentopography.org/plus); [OpenTopography subscriptions](https://opentopography.org/about/subscriptions)

**Download path D — State / local portals**
- North Carolina: statewide lidar in LAZ bulk downloads, NAD83(2011) State Plane NC; DEMs from QL1/QL2 lidar downloadable by tile at varying cell sizes from NC Spatial Data Downloads (sign-in with verified email) — [NC Spatial Data Download](https://sdd.nc.gov/); [NCSU Libraries: Elevation data sources](https://www.lib.ncsu.edu/gis/elevation)
- Minnesota: MnTOPO portal for viewing/downloading statewide elevation; second-generation lidar 2021–2024; statewide seamless 0.5 m lidar DEM (2025) — [MN DNR lidar](https://www.dnr.state.mn.us/maps/lidar/index.html); [MnGeo: Gen-2 lidar 2021–2024](https://www.mngeo.state.mn.us/chouse/elevation/lidar_gen2.html); [MN 2025 0.5 m DEM metadata](https://mnatlas.org/metadata/dem_lidar_2025.html)
- Texas: partial lidar coverage via TxGIO (Texas Geographic Information Office) — [Wikipedia: National Lidar Dataset (United States)](https://en.wikipedia.org/wiki/National_Lidar_Dataset_(United_States))
- King County (WA): 5-ft, 10-ft and 100-ft contour layers derived primarily from 2021 lidar, downloadable from the GIS Data Catalog — [King County contour005](https://www5.kingcounty.gov/sdc/?Layer=contour005); [contour100](https://www5.kingcounty.gov/sdc/?Layer=contour100)

**Using roof points to reconstruct building shapes**
- Overture's initial release derived heights for >6 million buildings from ~34,000 km² of 3DEP lidar by taking rooftop elevations and subtracting local ground elevation, using Microsoft/OSM footprints to locate buildings — [Overture building-heights whitepaper (PDF)](https://project.linuxfoundation.org/hubfs/Overture%20Maps/Building%20Heights%20Whitepaper_041423.pdf); [OSM US SotM 2023 talk](https://openstreetmap.us/events/state-of-the-map-us/2023/building-heights-from-open-usgs-lidar-to-open-overture-maps/)
- LoD2 roof reconstruction from airborne lidar is typically done in two steps — primitive (plane) extraction then roof-structure inference — with RANSAC plane detection and segment merging; uneven density causes over/under-segmentation and "obtaining regular, compact and topologically correct surface models from sparse and noisy point clouds remains a challenge" — [Point2Roof (ISPRS J. 2022)](https://www.sciencedirect.com/science/article/abs/pii/S0924271622002362); [Building roof plane extraction from LIDAR data](https://www.researchgate.net/publication/261305887_Building_roof_plane_extraction_from_LIDAR_data); [Automatic 3D building reconstruction from OSM + LiDAR (PMC)](https://pmc.ncbi.nlm.nih.gov/articles/PMC10007540/)

### Inferences
- For a residential lot (≈0.1–2 acres) the EPT clip is tiny: convert the parcel bbox to EPSG:3857, run a PDAL pipeline `readers.ept(filename="https://s3-us-west-2.amazonaws.com/usgs-lidar-public/<Project_Name>/ept.json", bounds="([xmin,xmax],[ymin,ymax])")` → `filters.range(limits="Classification[2:2]")` for ground or `[6:6]` for buildings → `writers.las` (LAZ). Find `<Project_Name>` from the `/boundaries` GeoJSON in hobuinc/usgs-lidar, usgs.entwine.io, or LidarExplorer.
- QL2's 10 cm RMSEz corresponds to ≈19.6 cm NVA at 95% confidence (1.96 × RMSEz, the ASPRS convention), i.e. ±0.6 ft — adequate for concept grading and drainage but not for finished-floor or pad elevations that a permit set will require from a surveyor.
- At ≥2 pts/m² (QL2) a 1,500 ft² roof has only ~280 points, so roof planes for a house are recoverable but ridge/eave lines will be approximate; QL1 (8 pts/m²) or a drone mesh is better for roof geometry.

### Gaps
- Exact QL0/QL1 RMSEz values could not be read from the USGS QL page (blocked); only densities/spacings were confirmed from secondary sources.
- The current (Sept 2026) count of EPT resources/points conflicts between sources (Hobu ">950 resources/10 T points" vs OpenTopography ">1800 datasets/42 T points"); OpenTopography's figure is more recent.
- PDAL's full option list (resolution, polygon, addons, threads) could not be fetched (pdal.io blocked; GitHub doc path returned 404); only `bounds` was confirmed.

## Key Question 3: Bare-earth DEM products (1 m, 1/3 arc-second), how to get a GeoTIFF clip (TNMAccess, OpenTopography usgsdem, Earth Engine), and DEM → contours

### Takeaway
The 1/3 arc-second (~10 m) seamless DEM covers all of CONUS/HI/territories; the lidar-derived 1 m DEM is the highest-resolution standard product and follows QL2 coverage (no official percentage found). Clip via TNMAccess/TNM, OpenTopography's `usgsdem` API (USGS1m is academic-only there; non-academics use OT+ or go to TNM/AWS), or Earth Engine `USGS/3DEP/1m`; make contours with `gdal_contour -a elev dem.tif contours.shp -i <interval>`.

### Cited Findings
- 1/3 arc-second DEM: "the highest resolution seamless DEM dataset for the U.S. with full coverage of the 48 conterminous states, Hawaii, and U.S. territories"; Alaska partial; distributed in geographic coordinates (NAD83), elevations in meters referenced to NAVD88 over CONUS; ground spacing ≈10 m N–S; pre-staged tiles in GeoTIFF — [USGS Science Data Catalog: 1/3 arc-second DEMs](https://data.usgs.gov/datacatalog/data/USGS:3a81321b-c153-416f-98b7-cc8e5f0e17c3); [ScienceBase 1/3 arc-second](https://www.sciencebase.gov/catalog/item/4f70aa9fe4b058caae3f8de5)
- 1 m DEM: introduced 2015 with limited coverage, expanding as QL2-or-better lidar is acquired; "highest resolution standard DEM offered in the 3DEP product suite"; a separate Seamless 1 m DEM collection exists (ScienceBase item created 2025) — [USGS: About 3DEP Products & Services](https://www.usgs.gov/3d-elevation-program/about-3dep-products-services); [ScienceBase: Seamless 1 meter DEMs](https://www.sciencebase.gov/catalog/item/67af83c1d34e5020fb91f170); [data.gov: 1 meter DEMs](https://catalog.data.gov/dataset/1-meter-digital-elevation-models-dems-usgs-national-map-3dep-downloadable-data-collection)
- 1/9 arc-second (~3 m) legacy DEM covers about 25% of CONUS — [USGS FAQ: coverage of 3DEP DEMs](https://www.usgs.gov/faqs/what-coverage-standard-3d-elevation-program-3dep-dems)
- USGS is migrating 3DEP DEMs to Cloud Optimized GeoTIFF (COG) on AWS; OpenTopography's USGS DEM requests subset those rasters on-the-fly and return a seamless mosaic for the AOI — [OpenTopography: USGS 3DEP Standard DEMs now available](https://opentopography.org/news/USGS-3DEP-DEMs-now-available); [OpenTopography: API access to USGS 3DEP rasters](https://opentopography.org/news/api-access-usgs-3dep-rasters-now-available)
- OpenTopography `usgsdem` endpoint serves 3DEP 1 m, 1/3 arc-second (10 m) and 1 arc-second (30 m) DEMs; the `globaldem` endpoint serves SRTM GL1/GL3, ALOS World 3D, COP30/90, NASADEM, etc.; "The USGS 3DEP 1m DEM is currently restricted to academic users" — [OpenTopography API docs](https://portal.opentopography.org/apidocs/); [OT 1 m DEM dataset page](https://portal.opentopography.org/raster?opentopoID=OTNED.012021.4269.3)
- bmi-topography (CSDMS) wraps the OT API; supported `dem_type` values include SRTMGL3, SRTMGL1, AW3D30, NASADEM, COP30, COP90, EU_DTM, GEDI_L3, GEBCOIceTopo, USGS30m, USGS10m, USGS1m ("limited to academic users"); key via `OPENTOPOGRAPHY_API_KEY` env var or `.opentopography.txt` — [csdms/bmi-topography](https://github.com/csdms/bmi-topography)
- Earth Engine `USGS/3DEP/1m`: 1 m pixel, bare-earth from lidar, NAVD88 vertical datum, UTM/NAD83, extent −171° to 164° lon, −16.6° to 76.9° lat, date range 2003-07-23 to present, provider USGS, public domain — [Earth Engine catalog source USGS_3DEP_1m.jsonnet](https://github.com/google/earthengine-catalog/blob/main/catalog/USGS/USGS_3DEP_1m.jsonnet); [EE catalog page](https://developers.google.com/earth-engine/datasets/catalog/USGS_3DEP_1m)
- Earth Engine's seamless 10 m asset `USGS/3DEP/10m` is marked deprecated; a 10 m spatial-metadata asset exists — [EE: USGS 3DEP 10m (deprecated)](https://developers.google.com/earth-engine/datasets/catalog/USGS_3DEP_10m); [EE: 3DEP 10 m metadata](https://developers.google.com/earth-engine/datasets/catalog/USGS_3DEP_10m_metadata)
- `gdal_contour` synopsis: `gdal_contour [-b band] [-a attr] [-3d] [-snodata n] [-f format] [-i interval] [-fl level...] [-p] [-nln name] src dst`; `-a` names the elevation attribute, `-i` sets the interval, `-fl` fixed levels, `-p` polygons instead of lines, `-3d` forces 3D vectors; example `gdal_contour -a elev dem.tif contours.shp -i 10.0` — [GDAL gdal_contour docs (source)](https://github.com/OSGeo/gdal/blob/master/doc/source/programs/gdal_contour.rst)
- QGIS has a sample processing model that creates a DEM and contours from a point cloud when PDAL-based algorithms are available — [Lutra Consulting: Native point cloud processing in QGIS](https://www.lutraconsulting.co.uk/blogs/native-point-cloud-processing-in-qgis)

### Inferences
- For CAD, generate contours with `-3d` so each polyline carries Z (`gdal_contour -a elev -3d -i 0.3048 dem_ft.tif contours.dxf` after converting the DEM to feet with `gdal_calc`), and choose the interval to match local code (1 ft for site plans is common). Using `-f DXF` writes directly to DXF for AutoCAD; a shapefile is preferable for Civil 3D's "Create Surface from contours" or Map 3D import.
- Non-academic users who need the 1 m DEM should skip OpenTopography and pull the 1 m GeoTIFF tile from TNM/TNMAccess (dataset "Digital Elevation Model (DEM) 1 meter") or derive their own ≤0.5 m DEM from the LAZ clip with PDAL `writers.gdal` — both are free and public domain.
- DEMs from TNM are in NAD83 geographic or UTM; reproject to the local State Plane (ft) with `gdalwarp` before Civil 3D import to avoid the transformation problems reported in Autodesk forums (see Question 7).

### Gaps
- No official 2026 percentage of CONUS covered by the 1 m DEM was found; USGS pages were blocked.
- The exact TNMAccess `datasets` string values (e.g. "Digital Elevation Model (DEM) 1 meter", "Lidar Point Cloud (LPC)") could not be confirmed from the blocked docs page.
- The exact `usgsdem` query-parameter names (e.g. `datasetName=USGS1m&south=&north=&west=&east=&outputFormat=GTiff&API_Key=`) could not be verified against the blocked API page; the report should link the API docs rather than hard-code them.

## Key Question 4: Building footprints — Microsoft, OSM/Overpass, Google Open Buildings, Overture, county layers

### Takeaway
Overture (ODbL, GeoParquet, 2.6 B buildings, heights partly from 3DEP lidar, CLI `overturemaps download --bbox … --type=building`) is the most convenient single source for a lot; Microsoft's US footprints (ODbL, GeoJSON per state, 129.6 M polygons, no heights) and Global ML footprints (heights for ~174 M structures) and OSM via Overpass (ODbL) are alternatives; Google Open Buildings does not cover the US.

### Cited Findings
- **Microsoft US Building Footprints**: 129,591,852 computer-generated footprints, all 50 states + DC, GeoJSON per state, ODbL license; 73.25 M footprints from 2019–2020 imagery, remainder averaging ~2012; polygon precision 98.5%, recall 92.4%, false-positive ratio <1%; no height attributes; per-state download pattern `https://minedbuildings.z5.web.core.windows.net/legacy/usbuildings-v2/<StateName>.geojson.zip` — [microsoft/USBuildingFootprints](https://github.com/microsoft/USBuildingFootprints)
- **Microsoft Global ML Building Footprints**: ~1.4 billion buildings from 2014–2024 imagery; height estimates for ~174 million structures (−1 where absent), with January–August 2026 updates adding heights from Vexcel and Maxar imagery primarily for the US, Belgium, Netherlands and Germany; format line-delimited GeoJSON in `.csv.gz` partitioned by country and level-9 quadkey; index `https://bfppub.blob.core.windows.net/$web/2026-08-13/dataset-links.csv` (hosting moved July 2026); also on Planetary Computer. The fetched README summary reports the license as "CDLA Permissive 2.0" — [microsoft/GlobalMLBuildingFootprints](https://github.com/microsoft/GlobalMLBuildingFootprints) (NB: earlier versions of this README stated ODbL; verify the current LICENSE file before relying on CDLA)
- **Overture Maps buildings**: theme published under ODbL because it includes OSM data, so other sources must be ODbL or compatible (e.g. CC BY 4.0); attributes include `height`, `num_floors`, `roof_shape`, `subtype`, `class`, facade/roof material and color; sources include OSM, Esri Community Maps, Microsoft, Google and Zenodo; "some building heights have been derived using lidar from USGS 3DEP" — [Overture Buildings Guide](https://docs.overturemaps.org/guides/buildings/); [Overture buildings schema concepts](https://docs.overturemaps.org/schema/concepts/by-theme/buildings/); [Overture 3D parts](https://docs.overturemaps.org/schema/concepts/by-theme/buildings/3d_buildings/)
- Overture buildings dataset contains over 2.6 billion building features — [Atlas.co: Overture buildings](https://atlas.co/data-sources/overture-maps/buildings/); in the 2026-08-19 release "hundreds of thousands of buildings picked up updated num_floors, height, and roof_shape values" — [Overture 2026-08-19 release notes](https://docs.overturemaps.org/blog/2026/08/19/release-notes/); [2026-02-18 release notes](https://docs.overturemaps.org/blog/2026/02/18/release-notes/)
- Overture data is hosted on AWS Open Data (GeoParquet) — [AWS Registry: Overture Maps](https://registry.opendata.aws/overture/); Esri publishes Overture in ArcGIS Living Atlas and is adding lidar-derived heights — [Esri blog: Overture Maps data in ArcGIS](https://www.esri.com/arcgis-blog/products/arcgis-living-atlas/announcements/overture-maps-data-in-arcgis)
- Overture CLI: `pip install overturemaps` (also brew/conda-forge/uvx); `overturemaps download --bbox=min_lon,min_lat,max_lon,max_lat -f geojson|geojsonseq|geoparquet --type=building -o out.geojson`; `overturemaps releases` lists versions; `gers` and `changelog` subcommands — [OvertureMaps/overturemaps-py](https://github.com/OvertureMaps/overturemaps-py)
- **OpenStreetMap / Overpass**: Overpass QL bbox query for buildings, e.g. `[bbox:S,W,N,E]; way[building]; out geom;` or `nwr["building"]({{bbox}}); out geom;`; `out geom` returns full geometry — [OSM wiki: Overpass turbo examples](https://wiki.openstreetmap.org/wiki/Overpass_turbo/Examples); [OSM wiki: Overpass API by Example](https://wiki.openstreetmap.org/wiki/Overpass_API/Overpass_API_by_Example); [OSM wiki: Overpass API](https://wiki.openstreetmap.org/wiki/Overpass_API)
- OSM data is ODbL; a Produced Work must include a notice "reasonably calculated to make any Person that uses, views, accesses, interacts with, or is otherwise exposed to the Produced Work aware that content was obtained from the Database" — [OSM wiki: Open Data License use cases](https://wiki.openstreetmap.org/wiki/Open_Data_License/Use_Cases)
- **Google Open Buildings**: targets Africa, South Asia, Southeast Asia, Latin America/Caribbean; the United States is not covered — use Microsoft or OSM there — [Google Research: Open Buildings](https://sites.research.google/gr/open-buildings/); [NextGIS: Google Open Buildings](https://nextgis.com/blog/google-ob/); building-level comparison of Microsoft vs Google footprints — [OSTI report](https://www.osti.gov/servlets/purl/2000384)
- **County layers**: King County publishes ~600 layers including building-related data with download/API options — [King County GIS Open Data](https://gis-kingcounty.opendata.arcgis.com/pages/download-gis-data)

### Inferences
- All three open footprint sources are ODbL (Overture, Microsoft US, OSM), so a DWG that embeds them and is distributed should carry an OSM/ODbL attribution note; this is a notice requirement, not a barrier to commercial use. Footprints derived by ML have ~1–2 m edge uncertainty (implied by 92% recall / satellite GSD) — fine for a base map, not for setback checks.
- Overture is the best first stop because a single bbox query can return the footprint plus `height`/`num_floors` where available (US coverage of heights is growing through 3DEP-derived and Microsoft/Vexcel/Maxar-derived estimates), giving a quick extrusion for the existing house before any lidar processing.
- County building-footprint layers (often digitized from 6-inch orthos) are usually more accurate than ML footprints; check the county open-data portal first.

### Gaps
- Overture's exact count of US buildings carrying `height` in the 2026 releases was not found.
- Microsoft Global ML license ambiguity (ODbL vs CDLA Permissive 2.0) could not be resolved because only a summarized README was retrievable.
- OSM wiki pages were summarized via search only (host blocked); Overpass public-instance rate limits were not captured.

## Key Question 5: Imagery — NAIP (resolution, license, access), state/county orthoimagery, commercial (Nearmap, EagleView, Vexcel, Maxar/Vantor), and whether commercial 3D meshes may be exported to CAD

### Takeaway
NAIP (public domain, 4-band, 60 cm standard since 2018 with 30 cm in some states, e.g. ~half of CONUS at 0.3–0.6 m in 2023) is free via Planetary Computer/Earth Engine/USGS services; many states and counties publish 6-inch (15 cm) orthos free. Nearmap explicitly supports exporting DSM, point cloud, textured mesh and true-ortho in OBJ/FBX/SLPK/3MX/B3DM/OSGB/GeoTIFF/LAS for subscribers with 3D-export permission and credits (prices are quote-only; user reports ~$2k+/yr small-business); Maxar/Vantor Precision3D is 50 cm / 3 m SE90 global; EagleView and Vexcel export/licensing terms were not publicly documented.

### Cited Findings
**NAIP (USDA FSA)**

- Maxar/Vantor's 50 cm / 3 m SE90 product is too coarse for a residential lot; it is included for completeness only.

## Key Question 6: Other height sources — NOAA Digital Coast lidar, 3DEP DSM vs DTM, FEMA lidar

### Takeaway
NOAA's Digital Coast Data Access Viewer is the best free "custom clip" service (draw AOI, pick LAS/LAZ/GeoTIFF, projection and datum) for coastal-state lidar; USGS 3DEP standard DEMs are bare-earth DTMs so a DSM must be built from first-return points; FEMA does not run a separate lidar portal but funds/uses 3DEP QL2 data.

### Cited Findings
- NOAA Data Access Viewer: search and download lidar, imagery and land cover "by user-defined geography", selecting from multiple file formats, projections and datums; draw tool subsets the data; custom processing recommended under 1.5 billion points; full datasets via HTTPS as LAZ in geographic coordinates — [NOAA DAV tool page](https://coast.noaa.gov/digitalcoast/tools/dav.html); [NOAA Coastal Topographic Lidar](https://coast.noaa.gov/digitalcoast/data/coastallidar.html); [NOAA DAV](https://coast.noaa.gov/dataviewer/)
- NOAA coastal lidar is also on AWS Open Data (`noaa-nos-coastal-lidar-pds`, LAZ index) — [AWS Registry: NOAA Coastal Lidar](https://registry.opendata.aws/noaa-coastal-lidar/); [LAZ index](https://noaa-nos-coastal-lidar-pds.s3.amazonaws.com/laz/index.html); NCEI Coastal Lidar Archive — [NCEI](https://www.ncei.noaa.gov/products/coastal-lidar-archive)
- Topobathymetric lidar (USACE NCMP/JALBTCX) datasets are mirrored on OpenTopography — [OpenTopography NOAA dataset example](https://portal.opentopography.org/noaaDataset?noaaID=10314); [NOAA topobathy](https://coast.noaa.gov/digitalcoast/data/jalbtcx.html)
- 3DEP standard DEMs represent "the bare-earth surface derived from lidar data" (i.e., DTM) — [EE catalog source USGS_3DEP_1m.jsonnet](https://github.com/google/earthengine-catalog/blob/main/catalog/USGS/USGS_3DEP_1m.jsonnet); OpenTopography's 3DEP notebooks generate DSM and CHM from the point cloud — [OT_3DEP_Workflows](https://github.com/OpenTopography/OT_3DEP_Workflows)
- FEMA: "Participation in 3DEP allows FEMA to be more proactive in its lidar collection"; FEMA standardized on QL2 per the USGS LBS — [USGS FS 2017-3081: 3DEP flood risk management](https://pubs.usgs.gov/fs/2017/3081/fs20173081.pdf); [FEMA Elevation Guidance Nov 2022](https://www.fema.gov/sites/default/files/documents/fema_elevation-guidance_112022.pdf)
- LidarExplorer also lists derived products: DEM, topobathymetric, and orthorectified radar image (ORI) — [USGS LidarExplorer](https://www.usgs.gov/tools/lidarexplorer)

### Inferences
- Build a DSM for the lot from the same LAZ clip with PDAL (`filters.range` to keep returns 1 or classes 2+6+vegetation, then `writers.gdal` with `output_type=max`) and a DTM with class 2 only; subtracting them gives a normalized height raster that directly yields existing-house ridge heights for zoning height checks.
- Coastal properties (FL, TX Gulf, Carolinas, etc.) often have newer/denser NOAA or USACE lidar than the 3DEP baseline, so check DAV before TNM.

### Gaps
- No FEMA-specific lidar download portal was identified; FEMA-funded collections are distributed through 3DEP/NOAA.

## Key Question 7: Drone photogrammetry — legality over your own property, workflow, software, outputs, accuracy, cost, into AutoCAD/Civil 3D

### Takeaway
Mapping your own lot to plan a development is "in furtherance of a business" and therefore NOT recreational under FAA rules — it requires a Part 107 Remote Pilot Certificate ($175 test, free certificate) plus $5 registration, Remote ID, ≤400 ft AGL, VLOS and LAANC in controlled airspace. Free/open WebODM (AGPL) or free-for-<$1M-revenue RealityScan/RealityCapture produce OBJ mesh, orthomosaic, DSM/DTM and LAS; with RTK or GCPs expect 1–3 cm horizontal / 2–5 cm vertical; ReCap Pro (~$305–405/yr) converts to RCP/RCS for Civil 3D surfaces.

### Cited Findings
**Legal (FAA)**
- Recreational flyers must pass TRUST (free, ~30 min, online); Part 107 pilots are exempt from TRUST; recreational registration is $5 for 3 years covering all drones; Part 107 registration is $5 per aircraft; both must keep VLOS; recreational pilots may not exceed 400 ft AGL — [Pilot Institute: Recreational drone rules 2026](https://pilotinstitute.com/recreational-drone-pilots-rules/); [FAA Recreational Flyers](https://www.faa.gov/uas/recreational_flyers); [FAA Getting Started](https://www.faa.gov/uas/getting_started)
- "Flying for work, payment, or as part of any business (even if not being paid) is not considered recreational flying"; FAA example: photographing a neighbor's property unpaid is not recreational because the purpose is not purely enjoyment; real-estate agents may not shoot listing photos under the recreational exception — [FAA FAQ: How is recreational flying defined?](https://www.faa.gov/faq/how-recreational-flying-defined); [FAA Safety Briefing: Flying for fun; but are you sure?](https://medium.com/faa/flying-for-fun-but-are-you-sure-54710c5448e6); [Know Before You Fly: Fly for fun](https://knowbeforeyoufly.org/whos-flying/recreational/)
- Part 107 knowledge test: $175 per attempt paid to PSI Services; FAA charges nothing for the application, TSA check or certificate; 14-day wait to retake; registration $5 per aircraft for three years — [Rotate: Part 107 test cost 2026](https://rotatepilot.com/guides/part-107-test-cost-and-scheduling); [Drone Launch Academy: Part 107 exam cost](https://dronelaunchacademy.com/resources/part-107-exam-cost/)

**Software (photogrammetry engines)**
- WebODM: GNU AGPL v3; produces georeferenced maps (orthophoto), point clouds, elevation models (DSM/DTM), textured 3D models and gaussian splats; "Official, up-to-date WebODM installers are free to download" — [OpenDroneMap/WebODM](https://github.com/OpenDroneMap/WebODM); hardware requirements — [WebODM docs](https://docs.webodm.org/installation/#hardware-requirements)

### Inferences
- Realistic all-in cost for a one-lot survey-grade drone map: Part 107 ($175) + registration ($5) + a sub-250 g or M3E-class drone ($750–$4,700) + free software (WebODM or RealityScan) + a rented RTK rover or 5–8 GCPs shot by a surveyor; without any GCP/RTK the model is internally consistent (relative accuracy at the GSD level) but absolutely mislocated by consumer-GNSS error, so it must be aligned to the lidar ground surface or to survey control before use.
- Practical import chain: photogrammetry → LAS (ground-classified) + OBJ mesh → ReCap Pro (index to RCP/RCS; optionally ReCap Photo instead of third-party software) → Civil 3D point cloud → TIN surface; the OBJ mesh itself goes to AutoCAD via 3ds Max/Blender FBX import or Civil 3D's mesh import for visualization only (Civil 3D surfaces need points/contours, not textured meshes).

## Key Question 8: Professional survey — what topographic/boundary/ALTA surveys deliver in DWG, 2025–2026 US cost ranges, and why lenders/permitting require them

### Takeaway
A licensed surveyor's DWG (boundary + topo, or ALTA/NSPS) is the only product that fixes the legal lot lines and certified elevations; 2026 US guides put boundary surveys roughly $380–$1,200 (up to ~$5,500 for complex lots), topographic $400–$1,500, ALTA $1,200–$4,000+, with wooded/hilly parcels adding 20–50%. Title companies and lenders require a survey for title insurance/closing and municipalities require a surveyed site plan for building permits.

### Cited Findings
- ALTA survey $1,200–$4,000 covering boundaries, topography, utilities, zoning, easements, rights-of-way and ownership elements; topographic survey $400–$1,500 mapping elevation, trees, water and ground features — [HomeGuide: Land survey cost 2026](https://homeguide.com/costs/land-survey-cost); [Angi: How much does a land survey cost (2026)](https://www.angi.com/articles/how-much-does-land-survey-cost.htm)
- Reported ranges: ALTA $1,200–$3,000 (some higher); boundary $100–$600 quoted for very simple lots with typical residential boundary surveys $1,200–$5,500; topographic $500–$1,200 — [Today's Homeowner: Land survey cost 2026](https://todayshomeowner.com/lawn-garden/cost/land-survey-cost/); [ALTA Survey Colorado: 2026 price guide](https://altasurveycolorado.com/average-cost-for-a-land-survey-2026-price-guide/); [My Site Plan: Land survey cost 2026](https://www.mysiteplan.com/blogs/news/land-survey-cost)
- Lot size and survey type drive price first; wooded, hilly or overgrown parcels add 20–50% because crews spend more time cutting sight lines and walking corners — [Landmodo: Land survey cost 2026](https://www.landmodo.com/blog/968/how-much-does-a-land-survey-cost-buyers-guide-2026)
- Site-planning surveys are typically required to apply for and obtain a building permit; plot plans are necessary for permits — [Exacta Land Surveyors: Survey types](https://exactaland.com/survey-types/); [Apex Survey: Site plan vs survey](https://apexsurvey.us/guides/site-plan-vs-survey)
- Mortgage/title surveys are typically required by title companies before issuing title insurance; many lenders require an ALTA survey before financing; house-location surveys are often required at closing; "lenders, title companies, and courts require surveys, not site plans, for boundary-related matters" — [Federal Title: 4 types of property surveys](https://www.federaltitle.com/blog/understanding-4-types-of-property-surveys); [SitePlanCreator: Site plan vs survey](https://www.siteplancreator.com/blog/site-plan-vs-survey-whats-the-difference)
- Topographic surveys locate man-made and natural features (fences, buildings, trees, rivers) and record their elevations — [Advanced Surveys: Survey by type](https://www.advancedsurveysinc.com/survey-by-type); survey longevity/when to update — [Millman Land: How long is a survey good for](https://millmanland.com/knowledge/how-long-is-a-land-survey-good-for/)

### Inferences
- The open-data model built from lidar/parcel GIS/footprints is a *pre-design* tool: it lets you test how many homes/tiny homes fit and rough grading before spending $2–6k on a combined boundary+topo survey, and the survey DWG (usually State Plane, US survey feet, NAVD88) then becomes the authoritative base that the open-data layers are re-aligned to.
- Cost figures across guides conflict (e.g., boundary "$100–$600" vs "$1,200–$5,500"); report both and attribute the low end to tiny platted lots with visible monuments.

- No source enumerated the exact DWG layer contents a surveyor delivers; this varies by firm and state standards.

## Key Question 9: Free desktop tools — QGIS, PDAL, GDAL, CloudCompare, LAStools, Blender GIS — role in the pipeline

### Takeaway
PDAL clips/filters EPT and LAZ and rasterizes DEMs; GDAL reprojects/clips rasters and makes contours (DXF-capable); QGIS (PDAL-backed point-cloud algorithms since 3.18/PDAL ≥2.5) is the GUI for all of it plus DXF/SHP export; CloudCompare (GPL) meshes point clouds (Poisson plugin) and handles OBJ/LAS; LAStools' core LASzip/LASlib are open but `lasground` etc. need a commercial license (free trial limited to a few million points); BlenderGIS/Blosm import GeoTIFF DEMs, shapefiles and OSM buildings for visualization.

### Cited Findings
- QGIS point-cloud algorithms require PDAL ≥2.5.0 and cover classification, noise filtering, height-above-ground, clustering and surface reconstruction; developed with Lutra Consulting, Hobu and Nyall Dawson; point clouds supported since QGIS 3.18 — [QGIS docs: Point cloud conversion](https://docs.qgis.org/3.44/en/docs/user_manual/processing_algs/qgis/pointcloudconversion.html); [QGIS docs: Point cloud extraction](https://docs.qgis.org/3.44/en/docs/user_manual/processing_algs/qgis/pointcloudextraction.html); [Lutra: Native point cloud processing in QGIS](https://www.lutraconsulting.co.uk/blogs/native-point-cloud-processing-in-qgis); [Gispo: Point clouds in QGIS 3.18](https://www.gispo.fi/en/blog/how-to-handle-point-clouds-in-qgis-3-18/)
- QGIS can export any layer to DXF (native DXF export and the Save_DXF plugin) and export elevation profiles to DXF/CSV — [QGIS Save_DXF plugin](https://plugins.qgis.org/plugins/Save-DXF/)
- PDAL `readers.ept` streams a bounded subset of an EPT resource (see Q2) — [PDAL readers.ept](https://pdal.io/en/stable/stages/readers.ept.html); PDAL/GDAL used by OpenTopography's 3DEP notebooks to make DTM/DSM/CHM GeoTIFFs — [OT_3DEP_Workflows](https://github.com/OpenTopography/OT_3DEP_Workflows)
- GDAL `gdal_contour` generates contour lines/polygons from a DEM to any OGR format (`-f`), with `-3d` and `-i`/`-fl` options — [GDAL gdal_contour docs source](https://github.com/OSGeo/gdal/blob/master/doc/source/programs/gdal_contour.rst)
- CloudCompare: GPL, free; reads LAS/LAZ and meshes; Poisson Surface Reconstruction plugin (PoissonRecon v7) needs normals computed first — [Wikipedia: CloudCompare](https://en.wikipedia.org/wiki/CloudCompare); [CloudCompare wiki: Poisson plugin](https://www.cloudcompare.org/doc/wiki/index.php/Poisson_Surface_Reconstruction_(plugin)); [CloudCompare GitHub](https://github.com/CloudCompare/CloudCompare)
- LAStools: LASlib and LASzip are free and open source; many tools (including `lasground`/`lasground_new`) require a license for commercial, government or production use but are free for non-profit personal, educational or humanitarian use; licensed tools can be tested free up to ~3–5 million points, after which output is slightly distorted; academic lab licenses EUR 2,000–3,000 — [LAStools LICENSE.txt](https://github.com/LAStools/LAStools/blob/master/LICENSE.txt); [LAStools site](https://lastools.github.io/); [LAStools GitHub](https://github.com/LAStools/LAStools)
- BlenderGIS imports shapefile, raster/GeoTIFF DEM and OSM XML, generates 3D terrain from DEM and extrudes OSM buildings by height attributes; Blosm (blender-osm) imports OSM buildings (height/floors), terrain and Google 3D Tiles — [domlysz/BlenderGIS](https://github.com/domlysz/blendergis); [BlenderGIS wiki: OSM import](https://github.com/domlysz/BlenderGIS/wiki/OSM-import); [vvoovv/blosm](https://github.com/vvoovv/blosm)
- Autodesk-side: ReCap converts LAS/E57/etc. to RCP/RCS for Civil 3D; Civil 3D imports LAS directly as a point cloud (see Q7) — [Autodesk Help: surface from point cloud](https://help.autodesk.com/view/CIV3D/2025/ENU/?guid=GUID-2F76077A-CA80-481F-B0D3-60BE636EF31C)

### Inferences
- Minimal free pipeline for one lot: (1) `pdal pipeline` with `readers.ept` + `bounds` → `filters.reprojection` to local State Plane → `writers.las` (LAZ) and `writers.gdal` (DTM/DSM GeoTIFF at 0.5 m); (2) `gdalwarp`/`gdal_translate -projwin` to clip the TNM 1 m DEM and NAIP COG to the parcel bbox; (3) `gdal_contour -3d` → DXF or SHP; (4) `ogr2ogr -f DXF` for the parcel GeoJSON and Overture/Microsoft footprints; (5) CloudCompare or WebODM for a mesh; (6) Civil 3D: import LAS as point cloud → surface, or import contours SHP → surface, attach ortho as image; ReCap only needed for RCP indexing of large clouds.
- Blosm's Google 3D Tiles import is technically possible but the Google policy cited in Q5 prohibits extracting or tracing that content, so it must be excluded from the legal workflow.

### Gaps
- No single cited source lists `gdal_translate -projwin`/`gdalwarp -te` clipping syntax (pages not fetched); the report should link https://gdal.org/programs/ generically.
- LAStools' exact free-trial point ceiling per tool is described only loosely ("~3–5 million points") in the license text summary.
