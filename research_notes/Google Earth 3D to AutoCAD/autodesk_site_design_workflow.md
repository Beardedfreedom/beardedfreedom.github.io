## KQ1. Plain AutoCAD (2025/2026): what 3D / geo data can it import natively, and what can't it do?

### Takeaway
Plain AutoCAD can attach ReCap point clouds (RCP/RCS only), import solid-modeling formats (STEP, IGES, SAT/Parasolid, Rhino 3DM, CATIA, SolidWorks, JT, NX, Creo) and 3DS meshes, geolocate a drawing to a coordinate system and drape Bing aerial imagery — but it has no native OBJ/glTF/FBX import, no LAS/LAZ/E57 reader, and no tool to build a TIN terrain surface from points, contours or DEMs; that requires Civil 3D (or a third-party add-on).

### Cited Findings
- **IMPORT command formats (3D solids/surfaces):** CATIA (.prt, .asm, .CATPart, .CATProduct), Creo/Pro-Engineer (.prt, .asm, .g, .neu), IGES (.igs, .iges), JT (.jt), NX (.prt), Parasolid (.x_b, .x_t), Rhino (.3dm), SolidWorks (.prt, .sldprt, .asm, .sldasm), STEP (.ste, .stp, .step); Autodesk notes "some formats … might not be available in all AutoCAD-based products" — [Autodesk Help: About Importing Non-Autodesk 3D Models](https://help.autodesk.com/cloudhelp/2023/ENU/AutoCAD-Core/files/GUID-2CF5CE0F-8049-459E-86C9-1826B41957F6.htm); [Autodesk Help: IMPORT (Command)](https://help.autodesk.com/cloudhelp/2022/ENU/AutoCAD-Core/files/GUID-81A5EE76-39A7-40A4-A5C5-E4921C03B33A.htm)
- AutoCAD can import 3D Studio (*.3ds) files (3DSIN) — [Autodesk support: What file formats can AutoCAD import?](https://www.autodesk.com/support/technical/article/caas/sfdcarticles/sfdcarticles/What-file-formats-can-AutoCAD-import.html)
- **FBX removed:** "Starting with AutoCAD Products 2019, support for the import and export of the FBX file format has been removed"; workaround is to append DWG in Navisworks and export FBX from there, or use AutoCAD 2018 — [Autodesk KB: Working with importing and exporting FBX files in AutoCAD Products](https://knowledge.autodesk.com/support/autocad/troubleshooting/caas/sfdcarticles/sfdcarticles/fbximport-and-fbxexport-removed-from-autocad.html); also [House of BIM: 2019 AutoCAD – R.I.P. FBXIMPORT](https://www.houseofbim.com/posts/2019-autocad-r-i-p-fbximport/)
- **OBJ / glTF:** AutoCAD has no native glTF import; converters (online or plug-in) are needed — [RapidPipeline glTF→AutoCAD guide](https://rapidpipeline.com/en/a/conversions-gltf-to-autocad/); [Automapki: Convert GLTF to AutoCAD](https://www.automapki.com/convert/gltf/gltf-to-autocad.html) (Automesher adds an `AmImportMesh` command to import glTF directly); [Innerscene glTF→DWG browser converter](https://www.innerscene.com/tools/gltf-to-dwg); [CAD Exchanger glTF→DWG](https://cadexchanger.com/gltf-to-dwg/)
- **Automesher LT** is a free AutoCAD add-on that imports/exports 3DS, OBJ, STL, OFF and PLY meshes; the paid **Automesher Application** adds STEP, IGES, SKP and conversion of meshes to true 3D solids — [Autodesk App Store: Automesher LT](https://apps.autodesk.com/ACD/en/Detail/Index?id=6592083963201800613&appLang=en&os=Win32_64); [Automapki: Automesher LT vs Full](https://www.automapki.com/news/comparing-automesher-lt-and-automesher-application-a-detailed-review.html); tutorial [Import STEP, STL, OBJ, 3DM & SKP to AutoCAD](https://www.automapki.com/tutorials/import-step-stl-obj-3dm-skp-and-other-3d-files-in-autocad.html)
- **Point clouds:** AutoCAD only accepts RCS and RCP; E57, LAS, PTX or XYZ must first be converted to RCS/RCP with Autodesk ReCap Pro — [Autodesk support: Which point cloud file formats can AutoCAD import?](https://www.autodesk.com/support/technical/article/caas/sfdcarticles/sfdcarticles/Which-point-cloud-file-formats-can-AutoCAD-import.html); E57 specifically: import into ReCap → save .RCP → attach in AutoCAD — [Autodesk support: How to import a .e57 Point Cloud into AutoCAD](https://www.autodesk.com/support/technical/article/caas/sfdcarticles/sfdcarticles/How-to-import-a-e57-Point-Cloud-into-AutoCAD.html)
- `POINTCLOUDATTACH` inserts an RCS scan or RCP project; found at Insert > Reference > Attach; dialog sets insertion point/scale/rotation, "Lock Point Cloud", "Show Details"; point clouds are references and not editable in AutoCAD — [Autodesk Help: POINTCLOUDATTACH (Command)](https://help.autodesk.com/cloudhelp/2022/ENU/AutoCAD-Core/files/GUID-E086391C-6CEA-4B70-A788-7630FD75469F.htm); [Autodesk Help: To Attach a Point Cloud to a Drawing](https://help.autodesk.com/view/ACD/2022/ENU/index.html?guid=GUID-6AA028D2-9F58-490B-B58E-B40F98BE245E); [S15 Studio: How to set up AutoCAD point cloud integration](https://www.s15studio.com/post/autocad-point-cloud-integration)
- **Geolocation / Bing imagery:** Insert ribbon > Set Location > From Map (or type `GEOMAP`); enter lat/long; GEOMAP works only with a *projected* coordinate system, not a geographic one; Map 3D/Civil 3D use `MAPCSASSIGN`, other AutoCAD products use `GEO` (GEOGRAPHICLOCATION); Autodesk has an agreement with Bing providing free aerial photography to Autodesk users, and the Bing copyright notice must be displayed on the drawing — [Graitec UK: AutoCAD & AutoCAD LT – Free Aerial Mapping](https://graitec.com/uk/blog/autocad-autocad-lt-free-aerial-mapping/); [Autodesk support: How to display Bing satellite imagery in AutoCAD Products](https://www.autodesk.com/support/technical/article/caas/sfdcarticles/sfdcarticles/Importing-Bing-images-into-AutoCAD-Map-3D-and-Civil-3D.html)
- The `GEO` command first requires a WGS84 lat/long position, which is then correlated to user-specified State Plane N/E coordinates; a forum reply notes that with a current AutoCAD subscription "Map 3D is available at no extra charge" and gives more robust geolocation than vanilla AutoCAD — [Autodesk Community: Geolocate drawing and overlay NAD83 Coordinate System](https://forums.autodesk.com/t5/autocad-forum/geolocate-drawing-and-overlay-nad83-coordinate-system/td-p/9771916)

- **TIN from points in plain AutoCAD:** Autodesk's own KB says to create a surface from AutoCAD points you use Civil 3D — [Autodesk support: To create a Civil 3D surface from AutoCAD points](https://www.autodesk.com/support/technical/article/caas/sfdcarticles/sfdcarticles/Creating-surfaces-from-AutoCAD-points.html); in the Map 3D forum the answer to "Create Surface from Points" is that "the only AutoCAD workflow is to use Civil 3D", with a community "Triangulate" LISP routine (draws a DTM of 3DFACEs on any AutoCAD variant) mentioned as the workaround — [Autodesk Community: Create Surface from Points (Map 3D forum)](https://forums.autodesk.com/t5/autocad-map-3d-forum/create-surface-from-points/td-p/9985470); "AutoCAD is NOT Civil 3D" — [MES Innovation](https://mes100.com/docs/autocad-is-not-civil3d/)

- **Mesh tools:** AutoCAD meshes "are often used to create terrain in civil or town planning"; `MESHSMOOTH` converts 3D faces and legacy polygon/polyface meshes to mesh objects; `MESHSMOOTHMORE/LESS` change subdivision — [Autodesk Help: MESHSMOOTH (Command)](https://help.autodesk.com/cloudhelp/2027/ENU/AutoCAD-Core/files/GUID-8823F3EB-A053-437A-94DB-081B654B8F3F.htm); [Autodesk support: How to convert 3D faces into mesh in AutoCAD](https://www.autodesk.com/support/technical/article/caas/sfdcarticles/sfdcarticles/Converting-3D-faces-into-mesh.html); [Autodesk Help: About Creating 3D Meshes (2024)](https://help.autodesk.com/view/ACD/2024/ENU/?guid=GUID-A6232957-5039-4AB7-8B1D-8FD0AD98F77B)

### Inferences
- For the user's stated data (LAS lidar, DEM rasters, contours, shapefiles, OBJ/glTF meshes), plain AutoCAD alone can only (a) view a ReCap-converted point cloud, (b) draw over contours/shapefiles imported via the bundled Map 3D toolset, and (c) bring textured OBJ/glTF meshes in only through a converter or Automesher. It cannot produce an existing-ground TIN, contours from lidar, or grading. The practical "you already have AutoCAD" path is: verify it is full AutoCAD (not LT), enable the Map 3D toolset for GIS/coordinate systems, and use a converter/free add-on for meshes — while accepting that terrain modelling will be approximate (3DFACE DTM via LISP, or mesh objects) unless Civil 3D or a paid add-on (Plex-Earth, Spatial Manager) is added.
- Because the 3DS importer still exists while FBX was removed, the least-lossy path for a textured OBJ/glTF mesh into plain AutoCAD is glTF/OBJ → (Blender or 3ds Max) → 3DS or DXF → AutoCAD; textures generally won't survive, only geometry.

## KQ2. Autodesk ReCap Pro / ReCap Photo: converting LAS/LAZ/E57 to RCP, photogrammetry, cost, bundling

### Takeaway
ReCap Pro is the required bridge for any LAS/LAZ/E57/PTS point cloud into AutoCAD or Civil 3D (it writes RCP/RCS and preserves LAS classification); it is included in the AEC Collection, sold standalone for roughly $305–$370/yr depending on source, and its cloud photogrammetry (ReCap Photo: up to 2,000 drone photos per aerial project, 300 for object projects) additionally consumes Flex tokens.

## KQ3. Civil 3D (2025/2026): existing-ground surface from lidar / DEM / contours, GIS import, coordinate systems, parcels, grading, roads, pads, cost

### Takeaway
Civil 3D is the Autodesk product that actually does the job: it attaches the ReCap RCP, filters to ground-classified points, builds a TIN via "Create Surface from Point Cloud" (with a distance-between-points thinning and non-ground filters), adds GeoTIFF DEMs and contour polylines directly to a surface definition, imports SHP via the Import GIS Data wizard/MAPIMPORT with automatic coordinate transformation, and provides parcels (lot layout tools), feature-line/grading tools (plus Grading Optimization for pads in the AEC Collection) and alignment-profile-assembly corridors for roads. Autodesk's own FAQ lists it at $360/mo, $2,870/yr, $8,610/3 yr (as surfaced 2026-09-28), though aggregators quote $2,430–$2,945/yr.

### Cited Findings
**Lidar → surface**
- Official Autodesk steps: prepare ReCap project (import LAS/LAZ, set input and target coordinate systems, review classification, delete non-ground points) then build the existing-ground TIN in Civil 3D — [Autodesk support: How to create ground surface from Lidar in Civil 3D](https://www.autodesk.com/support/technical/article/caas/sfdcarticles/sfdcarticles/How-to-create-ground-surface-from-Lidar-in-Civil-3D.html); companion article — [Autodesk support: How to create a surface from LiDAR data with Civil 3D](https://www.autodesk.com/support/technical/article/caas/sfdcarticles/sfdcarticles/How-to-create-a-surface-from-LiDAR-data-with-Civil-3D.html)
- Ground-only filter inside Civil 3D: Prospector > select point cloud > right-click > Edit Point Cloud Style > uncheck everything except "2 Ground"; then Prospector > Surfaces > Create Surface; right-click the point cloud > Add Points to Surface — [Autodesk support: How to create a Surface with Only Ground Points from Point Cloud Data in Civil 3D](https://www.autodesk.com/support/technical/article/caas/sfdcarticles/sfdcarticles/How-to-create-a-Surface-with-Only-Ground-Points-from-Point-Cloud-Data-in-Civil-3D.html)

## KQ9. Best-practice sequence for the user's exact goal, incl. units, vertical datum, file organization

### Takeaway
Sequence: (1) get USGS 3DEP LAZ/DEM, county parcel SHP and building footprints; (2) set the DWG coordinate system to the local NAD83 State Plane zone in the correct foot definition before importing anything; (3) build the existing-ground TIN from ground-classified lidar (via ReCap RCP) or the DEM, add contours/parcels/buildings as reference; (4) lay out lots, pads, roads and utilities in Civil 3D (parcels, feature lines, corridors, Grading Optimization); (5) model tiny homes as blocks/Xrefs; (6) visualize in Forma/InfraWorks/SketchUp. Sources confirm each step's mechanics and the unit/datum pitfalls; the ordering itself is an inference.

### Cited Findings
- USGS 3DEP lidar point clouds are distributed in LAZ (lossless compressed LAS) and can be loaded directly by many packages — [USGS: 3D Elevation Program distributing lidar data in LAZ format](https://www.usgs.gov/news/3d-elevation-program-distributing-lidar-data-laz-format); USGS 3DEP elevation map service — [USGS: New elevation map service from 3DEP](https://www.usgs.gov/news/technical-announcement/new-elevation-map-service-available-usgs-3d-elevation-program); USGS lidar base spec gives WKT CRS examples incl. NAVD88 — [USGS: Lidar Base Specification Appendix 5](https://www.usgs.gov/ngp-standards-and-specifications/lidar-base-specification-appendix-5-well-known-text-coordinate)
- Legal parcel boundaries come from recorded deeds/plats; county assessor GIS often publishes shapefiles/GeoJSON — [ATTOM: Where to find parcel boundary data](https://www.attomdata.com/news/most-recent/where-to-find-parcel-boundary-data/); nationwide commercial parcel layers (Regrid, ReportAll, ATTOM; Esri Living Atlas US parcel tile layer) — [Regrid](https://regrid.com/land-parcel-data); [ReportAll](https://reportallusa.com/); [Esri: US Parcel Boundary tile layer](https://www.esri.com/arcgis-blog/products/arcgis-living-atlas/announcements/us-parcel-boundary-tile-layer-now-available)
- **Feet:** US survey foot = 1200/3937 m; international foot = 0.3048 m exactly; NAD27 SPCS used survey feet, NAD83 SPCS is metric-based and US states differ in which foot they adopt; Civil 3D 2017+ has an explicit "US Survey Foot" unit; check via Toolspace Settings tab > right-click drawing > Edit Drawing Settings — [IMAGINiT: International Foot vs. Survey Foot](https://resources.imaginit.com/civil-solutions-blog/september-survey-series-part-1-international-foot-vs-survey-foot); [Autodesk Community: U.S. Foot vs Survey Foot](https://forums.autodesk.com/t5/civil-3d-forum/u-s-foot-vs-survey-foot/td-p/9729821); state-by-state coordinate-system picker — [E38 Survey Solutions: Coordinate System Selection by State](https://e38surveysolutions.com/blogs/news/coordinate-system-selection-by-state)
- **Vertical datum:** NAVD88 height in US survey feet is EPSG:6360 — [EPSG.io: NAVD88 height (ftUS)](https://epsg.io/6360); a search-surfaced lidar metadata example shows NAD83(2011) horizontal, NAVD88 Geoid 12B vertical, with *horizontal in international feet and vertical in US survey feet* (mixed units are common) — [rpls.com: Importance and effect of survey data, coordinate systems and Civil 3D topo](https://rpls.com/forums/ask-a-surveyor/civil-engineer-importance-and-effect-of-survey-data-coordinate-systems-and-civil-3d-topo/); LAStools discussion of "NAVD88 height – Geoid12A" in WKT/GeoTIFF — [LAStools Google Group](https://groups.google.com/g/lastools/c/BqKml7QPIik)
- Drawing coordinate system must be set before importing DEM/SHP/lidar and must match the data's datum/zone (see KQ3 citations: IMAGINiT IMG-as-DEM; Autodesk USGS GeoTIFF article; USGS lidar coordinate thread); ReCap lets you set input and target coordinate systems on import (Autodesk lidar article, KQ2/KQ3)
- InfraWorks IMX target coordinate system should equal the Civil 3D drawing's (KQ5 citation); Bing imagery misplacement when GEOGRAPHICLOCATION is used instead of C3D Drawing Settings (KQ3 citation)
- Data-exchange references for parcels ↔ GIS and feature lines ↔ SHP (WisDOT, IMAGINiT — KQ3)

### Inferences (the recommended sequence; ordering and Xref advice are inferences from the cited mechanics)
1. **Acquire:** USGS 3DEP LAZ tiles + 1 m DEM GeoTIFF; county parcel SHP; building footprints (county GIS, Microsoft/Open City Model, or OSM); optional drone photos for ReCap Photo.
2. **Coordinate system first:** in Civil 3D use Drawing Settings (not GEOGRAPHICLOCATION) to assign the NAD83 (2011) State Plane zone in the foot definition the state and the lidar metadata use; in plain AutoCAD use the Map 3D toolset's MAPCSASSIGN. Record the vertical datum/geoid (NAVD88, Geoid 12B/18) in the drawing title block; Civil 3D does not itself apply geoid separations, so keep everything in NAVD88 feet.
3. **Existing conditions:** ReCap Pro: import LAZ → assign source CRS → target CRS = drawing CRS → filter to class 2 ground → save RCP. Civil 3D: attach RCP → Create Surface from Point Cloud (distance-between-points ≈ 2–5 ft for a lot-scale site) → EG surface; or add the DEM GeoTIFF to a TIN surface definition as a fallback; import parcel and building SHPs with Import GIS Data; overlay Bing imagery (GEOMAP) for context only; keep contours as a check, not a source, if lidar is available.
4. **Design:** Sites/Parcels (Slide Line) for lots; alignments + profiles + assemblies → corridors for drives; feature lines for pads (offset inside setbacks) → grading or Grading Optimization with max/min slope constraints; slope-band surface analysis on the finished surface to confirm pad and driveway slopes; pipe networks/pressure networks for utilities if needed.
5. **Homes:** model each tiny-home type once as a DWG (or Revit/SketchUp → DWG) and place as blocks or Xrefs on pads; keep survey/EG, design surfaces, site plan, and units as separate DWGs Xref'd together with Data Shortcuts for surfaces/alignments.
6. **Visualize:** push the design surface + roads via IMX to InfraWorks, or export DWG/3D to SketchUp/Forma for massing, sun and wind studies; render or share via Autodesk Docs.

### Gaps
- No source directly documented a "tiny-home community" Civil 3D or Forma case study; the residential-subdivision materials (LinkedIn Learning residential course, AU residential grading class, parcel layout tutorials) are the closest practitioner sources.
- Whether Civil 3D 2026 applies geoid models when transforming vertical datums (vs. horizontal only) was not confirmed.
